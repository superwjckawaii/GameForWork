# P2 UI/UX 设计入口

> 状态：已记录需求，等待 P2 设计阶段逐项确认  
> 更新日期：2026-08-27

## 1. 目标

P2 对构筑、装备和仓库交互进行系统性升级。交互应参考成熟 PC 端 ARPG、挂机构筑游戏和仓库管理游戏的通用习惯，避免继续以“下拉框 + 操作按钮”作为主要方式。

本阶段先记录方向，不在 P1B 中临时加入不完整的右键或拖拽逻辑。

## 2. 已确认方向

### 2.1 装备右键菜单

- 装备格右键打开上下文菜单。
- 至少包含：装备、出售、锁定或解除锁定。
- 不适用的操作显示为禁用，并给出简短原因。
- 锁定物品不能被自动出售、自动分解或误操作销毁。
- 菜单后续应能按物品所在位置扩展为卸下、移动到仓库、移动到背包和标记制作底材。

### 2.2 拖拽换装与容器移动

- 支持从背包或仓库拖到角色装备槽直接换装。
- 支持装备槽之间、背包与仓库之间的合法拖拽。
- 拖拽开始后显示物品图标跟随、合法目标高亮和非法目标反馈。
- 在目标外松开、按 `Esc` 或窗口失焦时安全取消，物品必须返回原位。
- 换装导致旧装备被替换时，需要明确旧装备返回哪个容器以及容器已满时的处理。

### 2.3 角色装备备栏

- 构筑、仓库和装备相关页面提供常驻角色备栏。
- 备栏显示角色轮廓和正式装备槽位，并支持悬浮对比、右键和拖拽。
- 备栏同时显示核心槽、连接容量和因换装即将被禁用的技能连接。
- 主角与佣兵切换时，备栏必须明确当前对象；佣兵仍只允许玩家调整装备。

## 3. P2 需要继续确认的设计分支

- 右键出售是否立即执行、二次确认，还是进入可撤销的回购区。
- 锁定状态是物品实例属性还是仓库展示属性，以及是否随跨容器移动保留。
- 单击、双击、`Shift`、`Ctrl` 和快捷键的完整映射。
- 是否支持多选、批量锁定、批量出售和批量移动。
- 装备悬浮对比的数值范围：基础属性、词缀差异、容量变化、技能失效和预估战斗面板变化。
- 拖拽换装与掉落过滤器、临时收取箱、仓库已满规则之间的事务边界。
- 键鼠、不同 DPI、标准窗口和大窗口下的命中区域与可读性标准。
- 操作失败提示、撤销能力、回购期限和防误操作策略。

进入 P2 详细设计时，需要先调研并对比当前主流 PC ARPG 与挂机构筑游戏的实际交互，再逐项封版。

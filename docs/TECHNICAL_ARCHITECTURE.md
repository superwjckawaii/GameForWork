# GameForWork 技术架构基线

> 状态：已确认技术基线  
> 更新日期：2026-08-27  
> 说明：本文记录已经确认的开发方案；尚未确认的内容会明确标注。

## 1. 目标平台与技术栈

- 游戏引擎：Godot 4.7.2 .NET。
- 编程语言：C#，包括核心逻辑、Godot 表现层和 UI，不混用 GDScript。
- 渲染器：Compatibility Renderer，优先兼容办公电脑和低功耗显卡。
- 首发平台：Windows 10/11 x64。
- 首版不支持 Windows 32 位、Windows ARM、macOS、Linux、移动端或 Web。

用户提供的 Godot 可执行文件目标路径为：

```text
D:\OtherTools\Godot\_v4.7.2-stable\_mono_win64\Godot\_v4.7.2-stable\_mono_win64\Godot\_v4.7.2-stable\_mono_win64.exe
```

2026-08-27 本地只读检查中，该路径及 `D:\OtherTools\Godot` 根目录均不存在，因此目前只记录为目标路径，尚未验证实际 Godot 版本。

当前已验证的本地依赖：

- .NET SDK 8.0.424 可用，同时安装有 8.0.419。
- Git LFS 3.3.0 可用。
- 项目尚未创建 `global.json`；搭建代码工程时根据已验证的 Godot 版本固定 SDK。

## 2. 代码分层

采用纯 C# 核心与 Godot 表现层分离的结构：

```text
src/
├─ Game.Core/          纯 C# 游戏规则，不引用 Godot 类型
│  ├─ Combat/
│  ├─ Builds/
│  ├─ Items/
│  ├─ Maps/
│  ├─ Town/
│  ├─ Offline/
│  └─ Saves/
├─ Game.Godot/         场景、渲染、窗口、输入和音频
├─ Game.Content/       JSON 内容加载、稳定 ID 与 Schema 校验
└─ Game.Tests/         纯 C# 核心规则测试
```

分层约束：

- `Game.Core` 不依赖 Node、Resource、Vector2 等 Godot 类型。
- 核心状态不能直接序列化 Godot 场景或节点。
- AI、未来的玩家输入和离线结算向核心提交统一命令。
- Godot 层读取核心状态并负责渲染、动画、声音和桌面窗口行为。
- UI 全部使用 C#，不引入第二套脚本语言。

## 3. 战斗模拟

- 权威战斗逻辑以每秒 20 个固定模拟刻运行。
- 可见画面以 60 FPS 渲染，并对模拟状态进行视觉插值。
- 伤害、概率、冷却、资源和关键位置使用整数或定点数。
- 不让关键规则依赖平台浮点误差。
- 地图与战斗使用独立、可保存状态的随机数生成器。
- 同版本、同初始快照、同随机状态和同命令流必须产生相同结果。
- AI 与未来直接控制只是不同的命令生产者，不维护两套战斗规则。

## 4. 离线与快速结算

- 普通且已经稳定通关的地图允许快速解析。
- 新地图、高风险地图、Boss 和永久死亡任务使用完整固定刻模拟。
- 快速解析必须通过批量回归测试，与完整模拟的胜率、耗时、消耗和掉落分布比较。
- 快速解析不能用于永久死亡结论。
- 离线最多结算 48 小时。
- 离线结算开始前创建存档备份，完成后一次性事务提交。
- 当前版本不检测或惩罚系统时间修改；时间异常处理留待后续版本。

## 5. 回放与死亡报告

采用“初始快照 + 随机状态 + 命令流”方案：

- 不保存每个模拟刻的完整世界状态。
- 保存地图和战斗初始快照。
- 保存随机数生成器状态与外部命令流。
- 重新模拟生成完整回放。
- 额外保存关键节点、伤害来源、死亡原因和文字摘要。
- 旧版本无法精确重演时，仍能读取已经保存的摘要。

## 6. 存档架构

### 6.1 SQLite 是嵌入式存档

SQLite 作为游戏进程内的嵌入式文件数据库使用：

- 不需要安装数据库服务器。
- 不需要用户配置账号、端口或连接服务。
- 游戏直接读写本地存档文件，例如 `save.db`。
- 发布包只需要携带程序依赖，玩家不需要了解 SQLite。

### 6.2 存档内容

- SQLite 保存角色、物品、仓库、城镇、地图队列、事件记录和运行状态。
- JSON 保存技能、词缀、地图、敌人和其他只读内容定义。
- 装备变更、制作、招募和地图结算使用数据库事务提交。
- 不将 Godot 场景树或运行时节点直接写入数据库。

### 6.3 存档槽与备份

- 最多支持 3 个独立存档。
- 每 60 秒自动保存运行状态。
- 装备、制作、招募、交易和地图结算等关键操作立即保存。
- 保留最近 5 份滚动备份。
- 启动读取失败时自动尝试上一份有效备份。
- 存档包含明确的 Schema 版本和逐版本迁移程序。
- 时间统一保存为 UTC。

## 7. 数据驱动内容

- 内容定义使用 JSON，并在加载时进行 Schema 校验。
- 所有内容使用不可随显示名称变化的稳定 ID。
- 稳定 ID 使用命名空间，例如：

```text
core.skill.fireball
core.item.iron_sword
abyss.map.cracked_depths
dlc01.class.example
```

- 存档引用稳定 ID，不引用中文名称、资源显示名或可变文件路径。
- DLC 使用独立命名空间。
- 首版明确不支持玩家模组。
- 内部数据结构保留未来只读内容模组的可能性。
- 不允许未来模组代码直接进入核心存档进程。

## 8. 构建与发布

- 原型阶段提供 Windows x64 便携 ZIP。
- 1.0 优先通过 Steam 发布。
- Steam 版本由 Steam 负责更新。
- 非 Steam 版本首版不开发自动更新器。
- 每个正式版本记录内容版本、存档版本和 Git Commit。
- PNG、音频和大型美术源文件使用 Git LFS。

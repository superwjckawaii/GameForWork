# v0.5 第五阶段：战斗表现与压力验收

状态：已确定范围，待第四阶段动画修复和第三阶段内容接入后执行。

## 目标

第五阶段负责把战斗表现放进完整的经济、构筑、挂机和长时间运行压力中验收。它不更换引擎：当前客户端已经使用 Godot，实际渲染路径满足 60 FPS 基线；后续优先完善 Godot 的事件、绘制、粒子和材质层。只有出现明确的 3D 光照、大规模 GPU 粒子或超出现有渲染预算的需求，才重新评估引擎。

## 表现实现边界

1. **事件驱动**：表现只能从真实动作事件读取动作身份、来源、目标、起止时间、位置、方向、几何形状、半径、持续时间和轨迹。动画回放不能改变伤害、移动、掉落、收费或领取结果。
2. **分层与裁剪**：背景、地面危险、角色/敌人、弹道与命中、伤害数字、界面分别绘制；战斗表现限制在战场裁剪区内，不能覆盖状态栏、日志或按钮。
3. **像素素材**：可用高清素材作为源稿，再以最近邻缩放、有限调色板和硬边缘处理生成像素资源。正式资源必须记录源稿、输出尺寸、像素比例、透明度和导入设置；占位资源不得伪装成最终美术。
4. **材质与粒子**：ShaderMaterial 只用于受击闪白、边缘描边、溶解、护盾脉冲、危险区呼吸等局部效果；粒子只用于火花、烟尘、碎片和环境漂浮物。关键攻击几何和生效时刻必须由明确事件绘制，不能由粒子随机代替。
5. **镜头反馈**：重击、首领阶段切换和角色受创可以触发短促镜头偏移或轻微缩放；强度、时长和开关必须可配置，低特效档保留危险提示，不以抖动遮挡操作。
6. **引擎约束**：继续使用 Godot 现有 2D/CanvasItem 路径，不引入第二套战斗渲染框架；新增节点、粒子和材质必须说明生命周期、预算和销毁条件。

## 压力场景与指标

固定同一设备、分辨率和构筑输入，记录平均值之外的 95 分位、99 分位、最大帧和长帧数量：

| 场景 | 条件 | 重点 |
|---|---|---|
| 标准战斗 | 1 队伍、常规敌群、低/中/高特效 | 60 FPS、UI 可读性 |
| 多单位 | 双队伍、精英与首领同时存在 | 方向、目标、血条和危险边界 |
| 多投射物 | 高攻速、穿透/链/范围技能 | 弹道轨迹、命中时刻、对象回收 |
| 多地面效果 | 重叠危险区、持续区域和阶段切换 | 几何裁剪、预警时限、颜色区分 |
| 长时间运行 | 48 小时等效离线加动态画面压力 | 内存、节点/粒子泄漏、存档恢复 |

冻结门槛：标准 60 FPS；95 分位 ≤ 18ms；99 分位 ≤ 25ms；最大帧 ≤ 40ms；模拟峰值 ≤ 10ms；UI 刷新 ≤ 16ms；工作集 ≤ 700MiB。不得删除离群值或只用平均帧率宣布通过。

## 验收证据

- 每个压力场景保存输入种子、构筑、窗口、特效档、运行时长和设备信息。
- 每个代表技能保存连续帧或录屏，至少覆盖预警开始、移动/轨迹、命中/伤害、结束和阶段切换。
- 动态证据必须能对应稳定身份、生产入口和事件 ID；截图只能证明画面，不能代替运行时事件检查。
- 检查客户端重载、暂停、离线推进、失败恢复和重复回调，确认表现不会重复结算。
- 任一关键危险不可辨识、绘制越界、长帧超标、资源泄漏或事件与结算不一致，阶段保持未通过并记录修复项。

## 与其他阶段的关系

第四阶段先逐项修复动画身份、几何、时限、弹道和状态反馈；第五阶段再把这些修复放入完整战斗、挂机和经济压力。第六阶段只接收第五阶段所有阻断项关闭后的结果。UI 主题的通用悬浮和点击反馈属于共享基础，不把按钮动效误报为战斗表现验收。

## 验收口径与后续问题

第一阶段交付的是可执行规格、可追踪审计和优化前基线，不要求提前完成第四/第五阶段修复。代表场景数据覆盖检查已通过，但性能及引擎检查失败：最大帧62.0876ms，3帧超过40ms；WASAPI音频设备失效。完整原始数据、环境、截图、连续帧与校验值已随仓库归档，不能删除异常值或标为性能通过。

采样采用分层方案：两个场景各七种窗口/密度短样本，以及各三轮大窗高档长样本（预热30秒、采120秒）。完整42组合长采样及极限组合移至第五阶段；60张独立连续帧不是全程录像。标准60FPS、最大40ms等门槛不变，具体指标和局限见[前测报告](V0_5_VISUAL_BASELINE.md)。

第四阶段处理动画几何/时限/密度、弹道、时钟及越界；第五阶段定位长帧、在稳定设备环境复测音频错误，并执行完整矩阵、长期稳定性和经济验证；第六阶段仍须发布包验收。

## 不是第一阶段阻塞的后续工作

第二阶段实现港口行动与事件契约；第三阶段实现装备/宝箱/五词缀/三附魔；第四阶段修复动画并逐项验收；第五阶段平衡与压力验证；第六阶段发布。以上不应提前塞进规格阶段，也不能因为设计文件存在就标为已实现。

本轮新增面板、费用与权重作为用户“集中补齐”指令下的初始实现参数；与前面用户明确确认的核心机制区分记录。若后续调整，记录原因与审计证据，不更改已确认玩法边界。

## 第二阶段接续入口

按以下顺序实现同一条最小闭环，不重开已确认的产品问题：

1. 队伍准入与活动互斥：百级突破、队伍空闲、三档费用、余额校验和原子扣费；复用现有派遣边界。
2. 权威行动：固定三个区域，实际移动、接敌、避险、自动交互和撤离；用流程初始配置起步，不以评分判定胜负。
3. 状态恢复：进行中快照、固定随机序列、在线/离线等价、立即取消与停止重复的区别、失败停止/继续、损坏行动一次性退费。
4. 成功箱最小闭环：成功生成唯一箱，未开箱持续派遣，内容和顺序固定，开箱三选一、每箱原子领取、手选装备保护；18件底材、8件专属传奇和普通刷图装箱已接入，专属港区敌人及深度平衡仍在第三、五阶段。
5. 表现事件契约：动作身份、来源与目标、真实位置/方向/几何、生成与结束时间、轨迹；让第四阶段能够替换现有猜测式绘制。
6. 验证：收费与发箱防重、失败无箱、领取重入、满仓重试、退出恢复、双队伍互斥、相同输入在线/离线结果一致，再跑完整Release。

不要在第二阶段顺带扩展无光矿脉、第三队伍、策略选项或提前撤离；不要创建新一套平行的装备、战斗或奖励系统。第三阶段要替换旧结算消费者，而不是保留直接发奖再额外叠加宝箱。

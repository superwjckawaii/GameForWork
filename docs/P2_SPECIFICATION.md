# GameForWork P2 规格说明

> 状态：设计封版，允许进入开发
>
> 更新日期：2026-08-27
>
> 目标版本：`v0.2.0-p2`

## 1. 阶段目标

P2 是“主线解锁 + 构筑与物品管理”纵向切片。它不扩充新的异界机制，而是把 P1 已有系统组织成一套符合 PC ARPG 习惯、可长期扩展的正式界面，并补齐从新档开局到开启远征的完整路径。

P2 完成后，玩家应当能够：

- 用 60～90 分钟挂机完成精简五幕主线，并自然学会已有系统。
- 在通关第五幕前看不到远征主入口，通关后立即解锁远征管理页。
- 在同一工作区完成角色切换、属性查看、装备换装、仓库整理、技能连接、天赋规划和 AI 配置。
- 使用悬浮、双击、拖拽、右键和快捷键完成高频操作，不再依赖大量下拉框。
- 安全处理出售、分解、容量失效、满仓和旧存档迁移，不丢失任何无法恢复的物品。
- 在 `384×216` 小窗中看清战斗主体，在 `960×640` 标准窗口中完成全部管理操作。

## 2. 主导航与解锁

标准窗口主导航固定为：

1. `总览`
2. `主线`
3. `远征`
4. `角色与物品`
5. `城镇`

其中 `远征` 采用隐藏式门禁：

- 新档第五幕最终 Boss 完成前，主导航中完全不显示 `远征`。
- 第四幕开放地图掉落、地图仓库和主线页内的“门扉研究”预览，不提前显示远征导航。
- 第五幕最终 Boss 完成后显示 `远征`，但不自动启动第一张地图。
- 已通关旧档迁移后继续显示远征入口。

`总览` 负责两支队伍、城镇生产、库存警告、恢复箱警告和最近收益；不承载复杂编辑。

## 3. 精简五幕主线

### 3.1 内容结构

P2 使用正式五幕数据、解锁门禁和存档结构，但把首轮内容压缩为约 60～90 分钟。未来扩写至 4～6 小时时不更换数据模型。

五幕沿用：

1. 余烬营地
2. 饥饿边境
3. 沉没圣城
4. 无光之路
5. 门后之物

每幕固定 6 个线性节点，共 30 个节点：

- 3 个普通战斗节点
- 1 个剧情事件节点
- 1 个精英战斗节点
- 1 个幕 Boss

### 3.2 主线页面

- 中部：章节路线与节点状态。
- 右侧：当前任务、出战主角、预计收益和失败原因。
- 底部：可滚动剧情记录；剧情文字不使用阻塞弹窗。
- 点击“继续”后自动推进，直到失败、章节完成或全部主线完成。
- 主线只能由主角推进，不消耗地图或 Boss 碎片。
- 在线、托盘和真正退出后的离线时间都可推进主线。
- 普通节点、精英和 Boss 均自动尝试；战败后停止，提示调整构筑，不自动反复送死。

### 3.3 重玩与奖励

- 已完成的普通、精英和 Boss 节点可以重玩，用于经验和普通掉落。
- 固定剧情奖励、系统解锁和首通奖励只发放一次。
- 重玩不会重置章节进度，也不会再次触发解锁。

### 3.4 分幕解锁

- 开局：基础角色、装备栏和共享整理背包。
- 第一幕：仓库、掉落过滤器和工坊。
- 第二幕：佣兵、角色切换和第二支队伍相关信息。
- 第三幕：进阶、完整技能页、天赋页和 AI 页。
- 第四幕：地图掉落、地图仓库，以及主线页内的“门扉研究”预览。
- 第五幕：正式显示并开放远征页。

### 3.5 等级与天赋规模

- P2 主线支持角色升至 60 级。
- 天赋树扩充到约 70 个节点。
- 首轮主线结束时主角约 55～60 级，并获得与等级/剧情匹配的普通天赋点。
- 节点搜索、最短路径高亮和目标规划不消耗天赋点；只有明确确认加点才改变构筑。

## 4. 角色与物品工作区

### 4.1 页面结构

`角色与物品` 是一个统一工作区，顶部角色选择器、右侧角色摘要和装备备栏在四个二级模式间保持不变：

1. `装备与仓库`
2. `技能`
3. `天赋`
4. `AI`

默认布局：

- 顶部：当前角色、等级、职业和进阶。
- 中左：当前模式的网格、树或编辑器。
- 右侧：常驻纸娃娃装备栏、核心属性和容量摘要。
- “详细属性”抽屉：四个模式均可展开，默认收起。

核心属性摘要显示：

- 生命、法力、护盾
- 体魄、灵巧、精神、能量
- 主技能 DPS、有效生命、主要防御
- 抗性摘要
- 核心槽与连接容量

### 4.2 正式装备槽

P2 装备栏补齐：

- 武器、副手占用显示
- 头盔、胸甲、手套、鞋子、腰带、项链
- 两枚戒指
- 五个药剂位置（默认开放 3 个，其余按既有成长规则解锁）

P2 仍然只实现双手武器体系。装备双手武器后，副手槽以“已占用/不可用”显示，不新增单手、双持或盾牌。

手套、鞋子、腰带、项链和第二戒指进入正式掉落：

- 每个新增槽至少 2 种基础底材。
- 每类约 4～6 个适用词缀族。
- 可在主线普通掉落中出现。

### 4.3 共享整理背包与仓库

- 所有角色共用一个 20 格整理背包，不设置角色专属背包。
- 仓库与整理背包都使用一格一件的物品网格。
- 远征临时背包仍按队伍隔离，结算后清空。
- “最近掉落”是只读报告，不是可移动物品的第二份副本。
- 双击卸装优先进入最近使用的容器：整理背包优先，其次仓库。
- 系统强制弹出的物品依次进入整理背包、仓库、恢复箱。

### 4.4 恢复箱

恢复箱是永久安全兜底：

- 容量不设上限，内容永久保存。
- 玩家不能主动放入物品，只能取出。
- 技能容量失效弹出、存档迁移、修复流程和其他系统溢出都可写入。
- 恢复箱非空时，总览持续显示警告。
- 任何正常操作都不能以删除恢复箱物品来解决容量问题。

## 5. 统一键鼠交互

### 5.1 基础语义

| 输入 | 物品和管理界面的统一行为 |
| --- | --- |
| 悬浮 | 显示物品/节点说明、当前对比与假设换装结果 |
| 左键单击 | 只选择或聚焦，不执行破坏性操作 |
| 左键双击 | 装备自动穿戴；已装备物品自动卸下；非装备在整理背包与仓库间快速转移 |
| 左键拖拽 | 精确换装、卸装、跨容器移动和队列排序 |
| 右键 | 打开与当前位置相关的上下文菜单 |
| `Shift` + 左键 | 整理背包与仓库之间快速转移 |
| `Alt` + 悬浮 | 强制显示完整数值对比 |
| `Esc` | 取消拖拽、关闭菜单或退出当前临时状态 |

不可逆操作、批量操作和资源消耗操作必须使用明确按钮或菜单项，不绑定容易误触的单击。

### 5.2 拖拽事务

- 拖拽时物品图标跟随鼠标，合法目标高亮，非法目标给出原因。
- 合法装备格已有物品时执行原子交换；只有双方落位成功才提交。
- 在目标外松开、按 `Esc`、窗口失焦或目标在拖拽期间失效时完整回滚。
- 容器已满时取消玩家主动移动；系统强制移动则按恢复链路处理。
- 同一物品始终只有一个实例和一个正式位置。

### 5.3 右键菜单

根据物品所在位置显示：

- 装备或卸下
- 移入整理背包或仓库
- 出售
- 分解
- 锁定或解除锁定
- 标记或取消制作底材

不适用的操作显示为禁用，并说明原因。

## 6. 物品安全、出售与分解

### 6.1 锁定

- 锁定是物品实例的持久属性，跨容器移动后仍保留。
- 锁定物品不能被手动或自动出售、分解、制作消耗或过滤器处理。
- 已装备物品不能出售或分解，但不会自动变成锁定物品。

### 6.2 出售与回购

- 手动出售立即执行，不逐件弹出确认。
- 最近 20 件手动售出的物品进入永久保存的共享回购列表。
- 回购使用原出售价格。
- 自动过滤器出售的物品不进入回购。
- 回购超过 20 件时按最早售出顺序移除；批量操作预览必须提前提示会挤出的回购物品。

### 6.3 分解与批量操作

- 普通、魔法物品手动分解立即执行。
- 稀有、传奇物品手动分解需要确认。
- 批量出售或分解总是先展示数量、品质、收益和排除项摘要，再确认执行。
- 锁定与已装备物品自动排除，不允许通过批量确认绕过保护。

### 6.4 操作反馈

- 非阻塞结果使用右下角短时提示。
- 普通移动、排序等可逆操作提供短时撤销。
- 出售的长期恢复通道是回购，不与短时撤销重复。
- 底部历史抽屉保存最近 200 条操作、掉落和远征记录。

## 7. 换装比较与容量结果

普通悬浮显示精简差异，`Alt` 悬浮或详细属性抽屉显示完整假设结果：

- 基础属性与词缀差异
- 伤害、主技能 DPS 和攻击/施法相关变化
- 生命、护盾、有效生命、防御和抗性变化
- 属性需求是否满足
- 核心槽、连接容量变化
- 会被禁用或弹出的技能连接

比较仅计算“如果装备”的结果，不改变存档。确定换装后若容量不足，按既有优先级禁用连接，对应技能石依次进入整理背包、仓库或恢复箱。

## 8. 技能、天赋与 AI

### 8.1 技能

- 把重击、战吼、扩大范围、攻击速度、流血和生命消耗转为真实技能石实例。
- 技能石拥有物品格、等级和经验。
- 主动与辅助通过拖拽配置连接。
- 同名主动技能共享冷却的既有规则不变。
- 变体、品质和腐化留待后续版本。

### 8.2 天赋

- 以可缩放图形树展示约 70 个节点，不退回列表或下拉框。
- 支持搜索、匹配节点高亮、最短路径高亮、目标规划和属性汇总。
- 规划状态与已分配状态使用不同视觉和存档字段；规划不消耗点数。

### 8.3 主角 AI

主角 AI 编辑器支持有限但可组合的规则：

- 技能优先级
- 生命、法力或其他资源阈值
- 敌人数量、稀有度和距离
- Boss 条件
- 增益、减益和药剂条件
- 危险度条件

每条规则只允许一层 `全部满足` 或 `任一满足`，不实现任意嵌套逻辑树。战斗 AI 可以读取地图和敌人危险度，但不能读取未鉴定掉落结果。

### 8.4 佣兵

- 佣兵使用同一套角色页面和装备交互。
- 玩家可以调整佣兵装备。
- 佣兵技能、天赋和 AI 只读，并明确说明它们由自主成长决定。
- 不允许通过拖拽技能石或编辑规则间接改变佣兵成长配置。

## 9. 掉落过滤器与工坊

### 9.1 掉落过滤器

使用图形化有序规则列表：

- 规则按从上到下顺序匹配。
- 支持拖拽排序、启用/停用、克隆和删除。
- 支持匹配结果预览和“用当前选中物品测试”。
- 锁定物品不受过滤器自动处理。

### 9.2 工坊

- 工坊仍位于城镇页，不并入角色与物品二级导航。
- 复用统一角色选择器、物品选择器、悬浮和锁定规则。
- P2 提供 3 个确定性配方。
- 执行前显示材料消耗和制作前后对比。
- 不实现完整随机制作系统。

## 10. 远征管理页

### 10.1 布局

- 左侧：主角队/佣兵队切换与队伍摘要。
- 中部：共享地图仓库、当前选中队伍队列和拖拽排序区域。
- 右侧：路线方针与停止条件。
- 底部：当前进度、最近地图、战利品和错误记录。

### 10.2 地图交互

- 左键选择地图。
- 双击把地图加入当前选中队伍。
- 拖拽用于精确插入、排序和跨队伍移动。
- 右键菜单提供加入、移除、移动队伍等位置相关操作。
- 正在运行的地图不可移动或修改。
- 队列位置变化立即保存。

### 10.3 方针与停止条件

保留已有路线偏好、失败后停止/继续和仓库满处理，并新增：

- 最多连续运行 N 张地图
- 连续失败 N 次后停止
- 仓库空格少于 N 格时停止

所有启用的停止条件使用 `或` 关系，任意一个满足即停止。界面显示按当前库存和队列估算的最早触发条件。

方针修改先保留为未应用草稿，点击“应用”后保存；新方针从下一张地图生效，当前地图继续使用启动时的快照。

## 11. 旧档迁移

P1 旧存档迁移到 P2 时：

- 标记精简五幕主线已完成，远征保持解锁。
- 角色等级不足 60 时提高到迁移最低等级 60，不降低更高等级。
- 保留角色、物品、仓库、地图、资源和已有构筑。
- 依据迁移后的等级与一次性剧情奖励计算应得普通天赋点；减去现有已分配点后，把缺额作为未分配点补发，不自动替玩家加点。
- 发放一次免费完整洗点机会。
- 无法映射的位置、失效引用和系统弹出物品进入恢复箱，并生成迁移报告。
- 迁移在单一数据库事务中完成；失败则保留原数据库和现有备份，不写入半迁移状态。

## 12. 窗口、可读性与无障碍

- `960×640` 是完整管理界面的最小尺寸。
- 侧栏可以折叠，为中部网格、技能和天赋让出空间。
- `1920×1280` 使用整数 2 倍显示。
- 字体缩放支持 100%～150%，布局需要滚动或重排，不允许裁掉关键按钮。
- 稀有度、增减值、合法/非法目标不能只靠颜色表达，必须同时使用图标、符号或文字。
- 支持已确认的键鼠快捷键；手柄留到后续版本。

## 13. P2 美术方向

### 13.1 视觉目标

P1 当前资产的主要问题是细节密度过高，在小窗和任务栏尺度下容易变成噪点。P2 改为参考《TBH: Task Bar Hero》的设计取向：粗颗粒、强轮廓、低细节密度、极小尺寸仍可辨认。这里只参考小尺寸可读性和像素密度，不复制其角色、界面或资产。

### 13.2 像素规范

- 普通战斗角色目标包围盒约 `24×32` 至 `28×40 px`。
- 大型敌人约 `36×48` 至 `48×56 px`；Boss 约 `48×56` 至 `64×72 px`，特殊 Boss 可突破该范围。
- 每个小型角色使用约 12～20 个主色与明暗色，优先大色块和可识别剪影。
- 使用 1 px 深色外轮廓与有限的 1 px 高光，不使用抗锯齿、仿高分辨率纹理或密集抖色。
- 战斗地块可以保留 `32×16` 的 2:1 菱形规格，但减少表面碎纹，保证单位、掉落和危险预兆优先。
- 物品图标以 `24×24` 或 `32×32` 设计，先看轮廓即可区分槽位与大类。
- UI 使用扁平深色九宫格面板、1～2 px 边框、明确选中态和较少渐变。
- 标准窗口的剧情背景和 Boss 概念图可以比小窗战斗素材丰富，但必须与同一色板和轮廓语言兼容。

### 13.3 P2 资产范围

功能通过后统一生成并接入：

- 正式 UI 皮肤、面板和状态图标
- 全部装备槽与新增基础底材图标
- 五幕节点背景与章节标识
- 五个幕 Boss 的概念与战斗用简化像素形象
- 小窗用主角、佣兵和现有怪物的低密度替换资产

逐帧扩充角色动作不属于 P2；P2 继续使用有限帧或程序化位移，但必须保证画面刷新流畅、贴图裁切正确、没有相邻图块串入。

## 14. 技术实现边界

- 核心状态仍在纯 C# `Game.Core`，Godot 只负责显示与输入。
- UI 行为通过统一命令/事务服务提交，不允许每个面板各自直接修改物品位置。
- 每件物品必须拥有稳定实例 ID、唯一位置、锁定状态和必要的迁移版本。
- 主线、离线结算和远征继续使用确定性模拟；界面帧率不能改变模拟结果。
- 存档格式升级时保留现有 SQLite 主存档、滚动备份和损坏档案恢复规则。
- 玩家操作历史、回购和恢复箱需要持久化；短时 UI 撤销可使用会话级命令栈。

## 15. 开发批次

P2 内部保留四个本地提交，全部完成后只进行一次用户人工验收：

1. **数据与迁移**：主线、等级/天赋扩容、装备槽、技能石实例、物品位置/锁定、回购、恢复箱和 P1 旧档迁移。
2. **角色与物品 UI**：统一工作区、格子容器、纸娃娃、拖拽/双击/右键、比较、技能、天赋、AI 和过滤器。
3. **主线与远征**：30 节点主线、分幕解锁、离线推进、远征隐藏门禁、队列和方针编辑。
4. **美术、性能与验收**：TBH 方向低密度像素资产、UI 皮肤、贴图裁切修复、交互打磨、自动测试和性能验证。

这四个提交只作为本地可回退边界，不在中途要求用户逐批验收。完整 P2 本地验证通过后，用户统一体验；确认 `OK` 后再推送游戏代码。

## 16. 验收标准

P2 满足以下全部条件才可标记完成：

- 新档可完整挂机通关 30 个五幕节点，失败、恢复、重玩和一次性奖励正确。
- 通关前远征导航不可见；通关后出现且不会自动消耗地图。
- 旧 P1 存档迁移后保留进度和物品、远征可用、补点正确，并获得一次免费洗点。
- 角色/物品、技能、天赋、AI、过滤器和远征配置均可通过正式交互完成。
- 双击、拖拽、右键、锁定、回购、批量操作、恢复箱和满仓边界均有自动测试。
- 主线和远征的在线、托盘、离线结算保持确定性，48 小时结算继续满足既有性能门槛。
- 标准窗口目标 60 FPS，小窗失焦目标 30 FPS；战斗表现不得再出现约 1 FPS 的视觉刷新。
- 所有精灵图集裁切无串图，退出确认框和 100%～150% 字体缩放下无文字重叠。
- `scripts/verify.ps1` 的编译、`dotnet test`、Godot 启动检查和集成检查全部通过。
- 用户完成一次统一人工验收并确认 `OK`。
- 推送通过后创建 `v0.2.0-p2` 标签。

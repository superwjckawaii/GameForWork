# GameForWork P0 技术实现规格

> 状态：已确认，尚待实现  
> 更新日期：2026-08-27

## 1. 权威模拟数值

- 权威模拟频率为每秒 20 个固定刻，每刻 50 毫秒。
- 时间统一表示为整数模拟刻。
- 生命和伤害使用整数。
- 概率使用万分比，`10000` 表示 100%。
- 位置使用定点数，`1000` 表示 1 个逻辑地块。
- `Game.Core` 禁止使用 `float` 或 `double` 参与权威结果。
- Godot 表现层允许使用浮点数进行视觉插值，但不能反向修改核心状态。

## 2. 固定随机算法

- 核心层实现并固定使用 PCG32。
- 不使用 Godot 或 .NET 默认随机数参与权威结果。
- 每场战斗保存初始种子和 PCG32 内部状态。
- 地图、战斗和掉落系统未来使用相互独立的随机流。
- 随机调用必须来自明确的核心系统；渲染和 UI 不得消耗权威随机流。

## 3. P0 战斗场景

- 使用一个无障碍 `12×12` 逻辑菱形竞技场。
- 主角出生于 `(2, 6)`。
- 敌人出生于 `(10, 6)`。
- 双方由 AI 自动接近并攻击。
- 单场最长 30 秒，超时记为未分胜负。
- P0 不提供鼠标或键盘直接控制角色。
- 场景使用临时色块和简单像素轮廓。
- 界面提供“使用相同种子重新运行”功能。

### 4.2 敌人

```text
生命：70
移动速度：2.5 格/秒
基础攻击伤害：8
护甲：2
命中率：85%
攻击距离：1.25 格
攻击前摇：400 ms
```

### 4.3 P0 临时公式

```text
实际伤害 = max(1, 基础伤害 - 护甲)
```

- 命中失败仍然进入完整攻击冷却。
- 上述数值和公式只用于 P0 技术验证，不属于正式数值平衡。

## 5. 命令、事件与阶段

### 5.1 权威命令

- `MoveTo`
- `UseSkill`
- `Wait`

首个技能稳定 ID 为：

```text
core.p0.basic_attack
```

### 5.2 核心事件

- `ActorMoved`
- `CastStarted`
- `HitResolved`
- `DamageApplied`
- `ActorDied`
- `BattleEnded`

### 5.3 单刻处理顺序

```text
接收并排序命令
→ 开始施法
→ 移动
→ 完成前摇
→ 判定命中
→ 结算伤害
→ 处理死亡
→ 判断战斗结束
```

- 命令先按模拟刻排序，同刻再按角色稳定 ID 排序。
- 双方在同一模拟刻死亡时，战斗结果记为平局。

## 6. 状态、回放与哈希

每场战斗保存：

- 战斗格式版本
- 初始核心状态
- PCG32 随机状态
- 每刻外部命令
- 关键战斗事件
- 最终状态哈希

哈希规则：

- 使用规范化二进制状态的 SHA-256。
- 集合序列化前必须按稳定 ID 排序。
- 禁止依赖字典或哈希表的遍历顺序。
- 修改任意权威命令后，最终哈希应当改变。

## 7. P0 调试面板

P0 界面显示：

- 当前模拟刻
- 当前种子
- 双方位置、生命和冷却
- 最近 10 条战斗事件
- 当前状态哈希
- 暂停
- 单步执行
- 使用相同种子重播

调试面板在正式版本中可以关闭，不属于最终玩家 UI。

## 8. 自动测试

P0 至少实现以下测试：

1. 定点数四则运算与舍入。
2. PCG32 固定测试向量。
3. 同刻命令稳定排序。
4. 移动和攻击距离。
5. 攻击前摇和冷却。
6. 命中成功和失败。
7. 护甲和最低 1 点伤害。
8. 同刻死亡记为平局。
9. 快照序列化往返一致。
10. 命令流重播得到相同哈希。
11. 修改一个命令后哈希发生变化。
12. 同一种子连续运行 1000 次，最终哈希一致。
13. 1000 个不同种子无异常、死循环或越界状态。
14. 改变渲染帧率不影响权威结果。

`48 小时稳定内容低于 3 秒`属于指定本地环境的性能验收，不作为 GitHub Actions 的硬超时断言。CI 验证结果正确性，避免共享执行器性能波动造成误报。

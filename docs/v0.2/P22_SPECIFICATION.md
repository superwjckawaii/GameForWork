# P22 整合、平衡与 v0.2 封版规格

> 状态：已确认，全部采用推荐项
> 版本目标：`v0.2.0` 便携候选包

P22 不再增加主要玩法系统。它把 P16～P21 的战斗、构筑、掉落、界面和美术连接成一个可重复验收的完整版本，并只修复会阻挡封版的问题。

## 1. 完整流程

- 自动回归覆盖“创建角色（含启用或跳过教程）→五章剧情→T1→T16→100 级突破→T20→灰烬天垒→终局继续刷图”。
- 开发期允许加速运行；正式候选包必须逐项人工确认角色创建、页面解锁、主线/远征切换、装备与技能拖曳、天赋/升华/地图天赋、城镇建筑、过滤器、托盘和退出。
- 剧情与异界推进只读取实际战斗结算；失败继续使用既定的消耗损失规则，不在 P22 引入永久死亡。
- 清理全部测试占位画面及未完成入口。亡旗战场、沉金港和无光矿脉只写入 v0.3 文档，不出现在 v0.2 正式 UI。

## 2. 六套基准构筑与难度目标

- 使用 P18 固定的六套构筑：血征者、壁垒使、破阵者各一套开荒构筑和一套终局构筑。
- 开荒构筑用于剧情、T1、T10；终局构筑用于 T16、T20、灰烬天垒。
- 审计记录通关率、节点时长、死亡原因、伤害、承伤、恢复与资源收益。相同种子必须可复现。
- 推荐装备完整且技能/天赋正确时，剧情与 T1 不得形成无意义的站桩秒杀，也不能成为进度墙；T16～T20 和灰烬天垒保留明确构筑门槛。
- 普通地图目标约 1～3 分钟获得一次节点收益；Boss 和最终攻坚允许更长，但不得靠固定时间强制结算。

固定种子下的正式空间战斗结果见 [P22 六构筑空间战斗审计](P22_COMBAT_AUDIT.md)。

## 3. 经济与掉落封版

- T1～T10 基础地图续航目标不低于 `105%`；T16～T20 目标为 `90%～105%`，由危险度和地图数量加成继续改善。
- 地图数量加成同时影响装备、金币、金属、地图、技能石、完成奖励和固定 Boss 碎片。
- Boss 碎片不追加保底计数；过滤器只影响拾取/处理，不改变实际掉落抽取。
- 金币以 T1 为统一比较基准，复核建筑、附魔、打造、出售和回购价格；P22 只允许数值微调，不改变 P20 的掉落机制。
- 审计必须确认隐藏的白装/蓝装不进入背包，传奇定义与图标不串用，批量操作遵守稀有度和锁定规则。

固定 100,000 次/档位的最终结果见 [P22 经济蒙特卡洛审计](P22_ECONOMY_AUDIT.md)。

## 4. 性能与长稳门禁

- 标准窗口目标 60 FPS，小窗失焦目标 30 FPS；托盘关闭渲染并降低循环频率。
- 常规 UI 输入反馈目标不超过 100 ms；模拟 tick 通常低于 2 ms；48 小时离线结算目标低于 3 秒。
- Release 工作集峰值低于 700 MB；两小时热运行增长低于 80 MB；托盘平均 CPU 低于 2%。
- 正式发版前执行 2 小时前台、2 小时托盘和 48 小时离线全量门禁；日常开发允许短时同路径 smoke，报告格式保持一致。
- 验收矩阵覆盖标准、大窗、小窗，字体 `80/90/100/110/120/130/140/150%`，以及托盘隐藏/恢复、置顶开关和多次模式切换。

## 5. 存档与异常边界

- P22 固定会话格式版本 18。当前尚无外部用户，旧测试格式不再迁移；载入时移入 `recovery/legacy/` 并创建新档。
- 三个存档槽继续独立；后台自动存档合并重复请求，不阻塞 UI。
- 损坏文件永久保留在 `recovery/`，每一类最多 10 份，超过后只删除最旧文件。
- 异常必须写入结构化日志；正式候选包不得出现未处理异常、周期性卡顿或静默吞掉进度。

## 6. 美术与界面封版

- 装备、技能石和角色图集继续使用稳定 ID、固定 32 像素单元、透明边距与居中锚点。
- 装备底材按需求等级增加视觉阶级：低阶为粗糙/暗色，中阶增加明亮金属边与细部，高阶增加双层高光、贵金属/能量点缀；不同底材轮廓仍优先于色彩。
- Debug 专用的 20 倍速、模拟 48 小时、备份和性能读数只在编辑器/Debug 构建出现。
- 关闭询问框的“退出”和“缩到托盘”是显式动作；点击询问框右上角叉号只关闭弹窗，不改变窗口状态，也不保存选择。

## 7. 发布物与验收

- 门禁：Debug/Release 编译、`dotnet test`、素材边界/唯一性审计、Godot 导入、Godot 启动、短时稳定性 smoke 和 Windows Release 导出。
- 发布物为 `GameForWork-v0.2.0-win-x64.zip`；存档、设置和日志保存在 `LocalAppData`，不写入游戏目录。
- ZIP 包含 README 和版本说明；首版不做安装器、代码签名、Steam、联网、手柄和音频。
- 本次先推送候选提交，由用户实机验证；确认后再创建 `v0.2.0` 标签和 GitHub Release，不提前打正式标签。

## 8. 完成定义

只有在完整流程、六构筑审计、存档/托盘/窗口矩阵、全量自动门禁和便携包全部有可复现结果，且无阻断级异常时，P22 才视为完成。用户实机发现的问题使用后续修复提交处理，不改写已推送历史。

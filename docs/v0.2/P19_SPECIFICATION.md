# P19 装备底材与基础词缀库规格

> 状态：已实施（2026-08-29）
> 所属版本：v0.2
> 前置：P18 三升华与资源循环

## 1. 阶段目标与边界

P19 将当前约 42 种底材和少量双档词缀替换为正式的装备数据层，使装备生成、穿戴、加工、比较、过滤和后续 P20 掉落计算读取同一套规则。

同一词缀族在不同底材上的可用档位必须按该底材重新编号。例如戒指无法出现腰带专属的最高体魄档时，戒指自身最高的 `51–55 体魄` 仍显示为 T1；P1 早期 `+1～3 属性` 测试词缀不得再进入自然掉落池，旧测试存档中的该类词缀按正式区间归一化。

P19 负责底材、基础词缀、装备需求、品质、名称、生成合法性、词缀图鉴和数据审计；P20 负责实际掉落预算、掉率、价值估算和经济平衡；P21 负责约 80 种底材的最终独立图标；P22 再根据基准构筑和掉落审计微调数值。

## 2. PoE 数据直接导入原则

第一版不自行换算基础数值，直接采用选定 Path of Building Community 数据快照中的 PoE 基础底材数值与常规基础显式词缀库。主要输入为：

- `Data/Bases/*.lua`：底材需求、伤害、攻击速度、暴击、防御和固有属性。
- `Data/ModExplicit.lua`：常规前缀、后缀、等级门槛、数值范围、词缀组、标签和生成权重。
- `Data/ModFlask.lua`：适用于本作五种药剂的基础药剂词缀。

导入器必须记录源目录、源文件哈希和数据快照标识。游戏运行时只读取版本库内生成的 JSON，不读取 PoB、不访问外部数据库或网络。PoE 原始 ID 保留在调试/溯源字段中；稳定 ID 和玩家可见中文名称使用本作命名。

“直接采用”包括原始数值范围、物品等级门槛、权重、前后缀位置、词缀组和适用标签，不在 P19 中按本作 1～120 等级重新缩放。PoE 数据中本作没有对应战斗语义的词缀不生成死属性：弓、法杖、召唤物、图腾、陷阱、地雷等被范围过滤；可以映射到现有伤害、异常、技能标签或装备规则的词缀必须接入实际计算。

### 2.1 属性与伤害映射

| PoE 数据 | 本作字段 |
|---|---|
| Strength | 体魄 |
| Dexterity | 灵巧 |
| Intelligence | 精神 |
| 新增第四属性 | 能量 |
| Chaos Damage / Resistance 等 | 虚空伤害 / 虚空抗性等 |

本作不保留“混沌”伤害类型或混沌抗性。所有有实际对应机制的混沌基础词缀统一映射为虚空；只服务于毒、召唤物等未实现机制的条目过滤掉。

能量属性新增一套独立基础词缀族。其档位数值、物品等级门槛、适用槽位和生成权重第一版镜像精神属性词缀；它与精神属于不同家族，可以在同一件稀有装备上同时出现，总属性词缀池因此会自然扩大，P22 再评估是否需要降低权重。

## 3. 底材范围

正式目录固定为约 80 种：双手武器 12、单手武器 8、盾牌 8、胸甲 9、头盔 8、手套 6、鞋 6、腰带 5、项链 6、戒指 7、药剂 5。若原始数据筛选后数量需要微调，总量允许在 78～82 之间，但不得挤占单手武器和盾牌的完整成长路线。

- 武器同时具有单/双手及剑、斧、锤、长柄等标签。
- 防具覆盖护甲、闪避、护盾以及护甲/闪避、护甲/护盾、闪避/护盾三种混合底材。
- 每件底材具有需求等级和体魄、灵巧、精神、能量需求；需求不足不能穿戴。
- 常规底材沿用源数据的需求和解锁数值。101～120 级不额外制造膨胀版常规底材，保留给 Boss、神话、特殊加工和未来版本。
- 首饰、腰带、盾牌及部分武器保留原型固有属性并映射为本作字段。
- 不加入弓、法杖、权杖、匕首、爪、箭袋和召唤专属底材。

## 4. 品质与基础属性

品质上限 20%。武器品质局部提高底材物理伤害，防具品质局部提高底材护甲/闪避/护盾，药剂品质提高药剂效果或持续时间。所有局部修正先作用于底材，再参与全局属性计算；悬浮面板同时显示品质后的最终基础值和原始基础值。

## 5. 词缀模型

生成后的词缀目录预计约 90 个玩家可见词缀族、约 400 条分级记录，实际数量以适用于 P19 装备范围的 PoE 基础池为准，不为了凑数删除合法档位。

每条记录至少包含：稳定 ID、源 ID、玩家名称、前/后缀、家族、互斥组、T级、需求物品等级、一个或多个数值范围、属性类型、局部/全局语义、物品/词缀标签、来源、适用权重和展示顺序。

- 魔法装备生成 1～2 条词缀，前后缀各最多 1 条。
- 稀有装备生成 4～6 条词缀，前后缀各最多 3 条。
- 同家族和同互斥组均不得共存；复合词缀的全部组成属性参与合法性检查。
- 权重按底材标签、物品等级和来源确定，使用现有确定性随机源；候选顺序变化不得改变同快照的结果。
- 属性计算扩展到体魄、灵巧、精神、能量、生命/法力、四系抗性、护甲/闪避/护盾、攻击、暴击、格挡、法术压制、恢复、偷取、药剂和已实现技能标签。

P19 不导入势力、征服者、深渊珠宝、星团珠宝或赛季专属词缀。自然词缀、工匠词缀、破溃、附魔、腐化和传奇规则分别保存来源。工匠词缀占用正常前后缀槽位；附魔独立存在；破溃词缀不可被重铸；腐化装备不可继续常规加工。

当前固定快照包含 80 种底材，以及经本作战斗语义过滤后的数百个分级记录；具体数量由固定 JSON 与专项测试锁定。数量低于原始预估是因为导入阶段过滤了尚无本作战斗语义的召唤、图腾、陷阱、地雷、毒、弓与法杖专属记录；没有为达到数量目标保留死属性。

## 6. 孔组、传奇与名称

- 继续使用当前无颜色孔组，不增加 PoE 孔色与洗色。
- 底材决定基础核心孔和辅助连接容量，金属加工负责连接、改孔和高级附魔。
- 普通传奇从 12 件扩展到 24 件，神话保持 1 件；具体掉落归 P20，最终图标归 P21。
- 魔法装备根据主要词缀生成前后缀名称；稀有装备使用确定性词库生成专名；传奇名称固定。

## 7. 装备悬浮与词缀颜色

悬浮信息依次显示：稀有度与名称、底材、物品等级、需求、品质后基础属性、孔组、固有属性、显式词缀、工匠/破溃/附魔/腐化标记及锁定状态。

每条显式词缀显示实际值、可浮动范围、T级、需求物品等级和来源。词缀文字仍以装备稀有度和词缀类型为主色；T级只在同一色相内做轻微亮度变化，不使用彩虹色，不与传奇/稀有度名称争夺视觉焦点。建议亮度梯度为：

- T1：基准色亮度 +18%。
- T2～T3：+10%。
- T4～T5：+4%。
- T6～T7：基准色。
- T8及以下：基准色 -8%。

该颜色仅用于词缀行和 `Tn` 标记；必须同时保留文字 T级，不能只靠颜色表达。小窗 80% 字体缩放下仍需可读。

## 8. 词缀图鉴、过滤与排序

角色与物品页增加“词缀图鉴”侧栏，可按装备槽、底材、物品等级、前后缀、属性标签和来源筛选，公开所有可出现档位、数值范围、权重与需求等级。

现有掉落过滤器同步支持底材标签、指定词缀族、最高/最低T级和实际数值；仓库支持按物品等级、底材、稀有度、链接数和最高词缀T级排序。价值估算和经济排序留给 P20。

## 9. 存档与性能

测试阶段直接升级装备数据格式，不迁移旧装备实例；不兼容测试档进入 `recovery/legacy/`。导入后的目录在启动时加载一次，并按底材标签、物品等级、词缀位置和来源建立索引；实际掉落生成不得逐次解析 Lua/JSON或扫描全量目录。

## 10. 自动验收

1. 导入器输出固定快照与源文件哈希，相同输入生成字节一致的 JSON。
2. 底材总量为 78～82，且单手、双手、盾牌和六类防具路线均有完整等级跨度。
3. 基础词缀档位、数值范围、门槛、权重和组规则与选定 PoB 快照一致；混沌→虚空、精神→能量镜像有专项测试。
4. 需求、品质、局部/全局、抗性、格挡、压制、恢复和偷取进入实际角色/战斗计算。
5. 随机生成至少 100,000 件装备，验证无重复家族、无互斥冲突、无越级词缀、无非法标签和无空候选异常。
6. 魔法/稀有词缀数量和前后缀上限正确；制作、破溃、附魔与腐化遵守统一合法性规则。
7. 词缀图鉴、悬浮信息、T级亮度和过滤条件读取同一目录，不维护第二份展示数据。
8. Release 编译、全部单元测试、Godot 导入和无角色启动检查通过。
